# ConsoleCrypt Server 0.2.4

## Письма и страница аккаунта

- **Письма в HTML и текстом.** Каждое письмо (подтверждение адреса, сброс пароля,
  восстановление, вход с нового устройства, отзыв устройства, смена пароля,
  приглашение в команду и другие) приходит из двух частей: оформленная HTML-карточка и
  простой текст, обе в UTF-8. Язык писем задаёт `CC_MAIL_LANGUAGE=ru|en` (по умолчанию
  `ru`). Код для вставки в приложение показан всегда, со сроком действия. Кнопка-ссылка на
  `<CC_PUBLIC_URL>/account` появляется, только если задан `CC_PUBLIC_URL`; иначе письмо не
  упоминает веб-страниц.
- **Встроенная страница `/account`** (по флагу `CC_WEB_ACCOUNT=true`, по умолчанию
  выключена): подтверждение адреса, сброс пароля и восстановления по коду и ответ «Это не
  я» — без входа, cookies и доступа к хранилищу, со строгой CSP. Без флага сервер остаётся
  только API, и `/account` может отдавать ваш сайт. Docker Compose передаёт
  `CC_PUBLIC_URL`, `CC_WEB_ACCOUNT` и `CC_MAIL_LANGUAGE`; в Helm — `config.webAccount` и
  `mail.language`.
- **Письма без SMTP** — [HOSTING.md](https://github.com/evsikovas/consolecrypt-server/blob/main/docs/public/HOSTING.md):
  где взять коды из писем при `CC_MAIL_TRANSPORT=file` (файлы `.eml`) и как без почты
  подтвердить адрес или выдать код сброса командами `admin verify-email` и
  `admin reset-token`.

## Протокол 1.13 и 1.12

- **Отложенное удаление хранилища (1.13).** Ещё не доверенное устройство владельца с
  разблокированным хранилищем может запросить удаление; хранилище удаляется через 7 дней,
  а доверенное устройство отменяет запрос (`POST /v1/vaults/{id}/deletion/cancel`).
  Доверенное устройство по-прежнему удаляет сразу. Клиент 0.9.10 показывает предупреждение
  и кнопку «Сохранить хранилище».
- **Версии приложений устройств (1.13).** Сервер хранит версию, которую устройство сообщило
  последней; клиент 0.9.10 по ней не отправляет в хранилище объекты, которые старые
  версии на устройствах аккаунта не прочитают.
- **Подписанный ключ команды (1.12).** Владелец или администратор подписывает отпечаток
  ключа каждой эпохи; новый участник открывает команду, только если ключ совпадает с
  подписанным. Миграция `0015_team_key_commitments`.

Подробности — [PROTOCOL_CHANGELOG.md](https://github.com/evsikovas/consolecrypt-server/blob/main/PROTOCOL_CHANGELOG.md).

## Безопасность (проверка 26.10.2026)

- **Конверты команды.** Участник команды может удалить или заменить только свои
  конверты ключа; парольные и восстановительные конверты для команд запрещены.
- **Администраторы.** Назначить администратора может только владелец, как и в клиенте.
- **Приглашения.** Приглашение в команду получает только аккаунт с подтверждённым адресом;
  ответ сервера для остальных прежний.
- **Зависимости.** tokio 1.54.1 (RUSTSEC-2026-0386) и остальные обновления.

Миграции до `0015`. Клиенты до 0.9.10 продолжают работать: новые поля и маршруты
добавочные.

## English

### Mail and the account page

- **HTML and plain-text mail.** Every message (address confirmation, password reset,
  recovery, sign-in from a new device, device revoked, password changed, team invitation
  and others) has two parts: a styled HTML card and plain text, both UTF-8. The language
  comes from `CC_MAIL_LANGUAGE=ru|en` (default `ru`). The code to paste into the app is
  always shown with its validity. A button to `<CC_PUBLIC_URL>/account` appears only when
  `CC_PUBLIC_URL` is set; otherwise mail never mentions a web page.
- **Built-in `/account` page** (`CC_WEB_ACCOUNT=true`, off by default): confirm an
  address, reset the password or recovery by code and answer "This wasn't me" — no
  sign-in, no cookies, no vault access, a strict CSP. Without the flag the server stays
  API-only and your website can serve `/account`. Docker Compose passes
  `CC_PUBLIC_URL`, `CC_WEB_ACCOUNT` and `CC_MAIL_LANGUAGE`; Helm has `config.webAccount`
  and `mail.language`.
- **Mail without SMTP** — HOSTING.md: where to find the codes with
  `CC_MAIL_TRANSPORT=file` (`.eml` files) and how to confirm an address or issue a reset
  code without mail with `admin verify-email` and `admin reset-token`.

### Protocol 1.13 and 1.12

- **Pending vault deletion (1.13).** An owner's device that is not trusted yet, with the
  vault unlocked, can ask to delete the vault; it is deleted after 7 days, and a trusted
  device cancels the request (`POST /v1/vaults/{id}/deletion/cancel`). A trusted device
  still deletes at once. Client 0.9.10 shows a warning with "Keep the vault".
- **Device app versions (1.13).** The server keeps the version each device last reported;
  client 0.9.10 uses it to keep vault objects that older apps on the account cannot read
  out of the vault.
- **Signed team key (1.12).** An owner or admin signs the fingerprint of each epoch's
  key; a new member opens the team only when the key matches. Migration
  `0015_team_key_commitments`.

Details: PROTOCOL_CHANGELOG.md.

### Security (review of 26.10.2026)

- **Team envelopes.** A team member can delete or replace only their own key envelopes;
  password and recovery envelopes are refused for teams.
- **Admins.** Only the owner appoints admins, as in the client.
- **Invitations.** Only an account with a confirmed address receives a team invitation;
  the response is unchanged for the others.
- **Dependencies.** tokio 1.54.1 (RUSTSEC-2026-0386) and the other updates.

Migrations up to `0015`. Clients before 0.9.10 keep working: the new fields and routes
are additive.
