# ConsoleCrypt Server 0.2.0

- Enterprise-режим входа (`CC_AUTH_MODE=enterprise`, Helm `auth:`), по умолчанию
  выключен: вход в аккаунт только через корпоративный IdP по OIDC (пресеты Entra
  ID, AD FS 2016+, Keycloak, Google Workspace, Okta, generic) или Active
  Directory / LDAP (ldaps:// или STARTTLS, сервисная учётка + bind пользователя,
  вложенные группы, `objectGUID`). Регистрация, вход, сброс и смена пароля
  аккаунта и подтверждение почты в этом режиме отвечают
  `enterprise_auth_required`.
- OIDC: сервер — конфиденциальный клиент IdP с PKCE, `state` и `nonce`;
  приложение получает одноразовый `login_code` (60 секунд, привязан к PKCE
  приложения и устройству). Проверка ID token: RS256/PS256/ES256 через JWKS,
  точные `iss`/`aud`/`azp`/`exp`/`iat`/`nonce`, один ограниченный перезапрос JWKS
  при неизвестном `kid`. Обязательная группа/роль/claim, MFA по `amr`/`acr`,
  допустимые домены, автосоздание аккаунтов.
- Существующие аккаунты привязываются при первом входе (email + домен из
  `CC_AUTH_ALLOWED_DOMAINS`), пароль аккаунта удаляется; аккаунт другого
  источника не захватывается (`identity_conflict`).
- Перепроверка пользователя в IdP/AD не чаще `CC_AUTH_RECHECK_MINUTES` — при
  обновлении токена и фоновым проходом: отключённый, удалённый или вышедший из
  группы сотрудник теряет все сессии (`account_disabled`); при недоступном IdP/AD
  сессии живут `CC_AUTH_RECHECK_GRACE_HOURS`.
- Защита учёток AD от блокировки через сервер: попытки входа по LDAP считаются в
  PostgreSQL на логин, пользователя AD и IP; после `CC_LDAP_MAX_FAILURES` за
  `CC_LDAP_FAILURE_WINDOW_MINUTES` — `429` без обращения к AD.
- Проверка IdP/AD при старте; команды `admin auth status|test`,
  `admin identity link|unlink`, `admin session revoke`; `admin list-users`
  показывает способ входа.
- Миграция `0011_enterprise_auth`: `users.password_hash` становится
  необязательным; таблицы `account_identities`, `oidc_flows`, `oidc_login_codes`,
  `ldap_login_failures`, `auth_provider_status`. Существующие данные не меняются.
- Документация: [Enterprise-режим](../../../docs/public/ENTERPRISE.md) с рецептами.

Протокол **1.9** только добавляет `capabilities.auth`, эндпоинты
`/v1/auth/oidc/*` и `/v1/auth/ldap/login` и коды ошибок; клиенты протокола 1.7 и
старше продолжают работать с сервером в режиме `standard`. Сервер по-прежнему
ничего не расшифровывает.

## Общие заметки

- Общие заметки к общим объектам: участники общего хоста, подключения к базе
  данных или контекста Kubernetes ведут зашифрованные заметки к нему. Флаг
  `CC_SHARED_NOTES_ENABLED` (в Helm — `config.sharedNotesEnabled`),
  по умолчанию выключен; требует `CC_OBJECT_SHARING_ENABLED`. Объявляется как
  `supports_notes_v1` в `/v1/shares/capabilities`.
- Ключ заметок каждой эпохи доступа выдаёт и подписывает устройство владельца;
  каждую заметку подписывает устройство автора. Сервер проверяет членство,
  авторство, эпоху и подписи и хранит только шифротекст.
- Маршруты: `GET /v1/shares/{id}/notes`, `PUT /v1/shares/{id}/notes/keys`,
  `PUT|DELETE /v1/shares/{id}/notes/{note_id}`,
  `POST /v1/shares/{id}/notes/rekey`.
- Лимиты: 500 заметок на объект, до 288 KiB шифротекста на заметку.
- Миграция `0010_share_notes`: `shared_note_keys`, `shared_notes`.
