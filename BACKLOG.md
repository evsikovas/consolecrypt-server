# Бэклог эксплуатации

## SMTP на production — отложено до ответа провайдера

- [ ] Включить почту и регистрацию на `sync.consolecrypt.dev` после устранения сетевого ограничения.

**Статус на 19 октября 2026:** владелец отправил заявку провайдеру VPS и попросил
отложить почту. API и синхронизация работают. На VPS оставлены
`CC_MAIL_TRANSPORT=disabled`, `CC_REGISTRATION_OPEN=false` и обязательное
подтверждение email. Восстановление пароля и другие почтовые операции недоступны.

Проверено:

- `smtp.masterhost.ru` разрешается на Mac и VPS в один IPv4-адрес; AAAA нет.
- С VPS подключения к портам 25, 2525, 465 и 587 заканчиваются TCP timeout.
  Локальный firewall VPS не блокирует исходящие соединения; место сетевого
  ограничения пока не установлено.
- С Mac порт **2525 поддерживает STARTTLS**, сертификат и имя сервера проверены.
  На **465 с TLS** также проверена авторизация. Писем при диагностике не отправляли.
- Логин, пароль и отправитель хранятся отдельно от Git; в этот файл их не добавлять.

После ответа провайдера:

1. С VPS повторить TCP, STARTTLS и проверку сертификата для
   `smtp.masterhost.ru:2525`, затем проверить авторизацию без отправки письма.
   Альтернатива — порт 465 с TLS. Не отключать проверку сертификата и не передавать
   реквизиты по незашифрованному соединению.
2. Сохранить приватную резервную копию `/opt/consolecrypt/api/server.env` и внести
   SMTP-реквизиты: `CC_SMTP_HOST=smtp.masterhost.ru`, `CC_SMTP_PORT=2525`,
   `CC_SMTP_TLS=starttls`, `CC_MAIL_TRANSPORT=smtp`, разрешённый отправитель и
   действующие логин/пароль. Файл оставить с правами `0600`; не исполнять его
   через `source` и не печатать секреты в журнал.
3. Пересоздать только сервис `server` существующего проекта, сохранив release overlay:

   ```sh
   docker compose --project-directory /opt/consolecrypt/api \
     --project-name consolecrypt-api \
     --env-file /opt/consolecrypt/api/server.env \
     --file /opt/consolecrypt/api/compose.yaml \
     --file /opt/consolecrypt/releases/server/compose.release.json \
     up -d --no-deps --wait --force-recreate server
   ```

4. Проверить `/readyz`, `/v1/meta` и доставку подтверждения email/восстановления
   пароля на согласованном тестовом адресе. После успешной проверки включить
   `CC_REGISTRATION_OPEN=true` и повторить пересоздание сервера той же командой.
   Требование подтверждения email сохранить.
5. Проверить свежий экспорт базы и конфигурации на NAS, отметить задачу выполненной
   и записать дату проверки доставки. Для настройки SMTP новый образ и тег не нужны.
